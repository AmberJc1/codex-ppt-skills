# 导出与验证

仅在合并、导出或修正PPT时读取。

## 共用布局数据

从最终HTML提取或创作时同步维护：画布尺寸、层级、形状路径与样式、图片原文件与裁切、段落文字及位置/字体/字号/颜色/换行。

浏览器提取前等待图片与字体加载，隐藏画布外控件，统一坐标原点。SVG内部坐标经过变换矩阵换算；带强调标签的段落仍视为一个文本块。CSS伪元素、斜切框、圆形、箭头、透明度、图片遮罩与裁切不能漏掉。过滤隐藏节点与无效坐标，避免重复导出父级段落及其子文字。

可通过浏览器字符范围恢复实际换行，但PPT不能每字建框。提取器不支持的CSS效果，应改用可编辑的简单形状、受支持SVG结构或用户允许的装饰图片，不能将正文栅格化。

## 画布与背景

识别背景图的有效区域，裁去灰白外围。旧HTML尺寸不一致时，统一前景的比例与坐标，单独将有效背景覆盖目标画布。不能非等比拉伸文字/人物修复灰边。必要时调整边距与对象位置。

检查背景对象偏移为0、宽高等于页面尺寸；标题条等装饰应正确裁切或调整，不能依赖画布外图形遮挡灰边。

## 原生PPT

使用当前 presentations 技能指定的生成与最终化方式。段落生成一个原生文本框，框内多行与富文本，不拆成零散字框。显式设置字号、字体、行距和内边距，关闭意外的自动缩放。制表位和字符间距通过实际渲染核对。

流程节点、框、箭头和结构图用可编辑形状；原图保持比例、透明通道和裁切。中文、拉丁和艺术字分别记录字体。当前电脑显示正常，不代表另一台拥有同样字体；允许时嵌入，否则说明需要的字体。

用PowerPoint或可用WPS打开并导出逐页预览，不把浏览器渲染当作PPT验证，不声称使用未实际运行的软件。

## SVG整段文字

正文采用单个 `<text xml:space="preserve">`，内含实际换行字符，禁用 `<tspan>`、`foreignObject` 和文字轮廓化。仅写换行与 `white-space: pre` 不保证所有阅读器正确显示多行。

可以在同一个 `<text>` 内提供与字符内容对应的 `x`、`y`坐标列表，使多行预览仍是一个文本对象。换行、空格、中文与非BMP字符的对应由生成器处理并实测。也可使用目标软件已验证支持的布局机制。

SVG局部字号/颜色常依赖 `<tspan>`。用户禁止时，正文使用一致样式，独立标题或标签另建对象；PPT在单一文本框中保留富文本。不能宣称SVG完全保留混合文字样式。

SVG转换后的分组、字体、换行取决于Office版本。未经目标软件转换验证，不保证单个文本框或像素级一致。最终可编辑PPT直接生成原生对象作为可靠交付。

## 检查与交付

1. 核对批准的页码和顺序，不漏页或加页。
2. 完成 presentations 技能要求的包结构、布局与字体检查。
3. 实际办公软件逐页渲染，重点看编号节点、图示小字、多人介绍、艺术字、页底总结。
4. 检查文字完整、透明人像、背景覆盖四边和画布边界。
5. 局部修改只复查受影响页；共用画布与字体改动回看全部受影响页。
6. 交付链接指向最新文件，SVG包与PPT来自同一最终稿。

本技能基本结构检查（Python路径由当前环境发现）：

```text
python scripts/check_exports.py --pptx <完整PPTX路径> --svg-dir <逐页SVG目录> --expected-pages <页数>
```

仅检查对象、页数、SVG结构，不证明排版质量、字体渲染、段落分组语义或Office转换兼容性。
