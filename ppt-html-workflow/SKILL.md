# 逐页制作可编辑PPT

按“大纲 → HTML → 逐页修改 → 合并导出”工作。HTML用于设计预览，最终交付原生可编辑PPTX和逐页SVG，不能用整页截图代替可编辑幻灯片。

## 开始时

- 检查报告、图片、模板和已有HTML，建立来源与页码清单。继续已有成果，避免从头重做。
- 报告用于确定事实，模板与截图用于参考版式；不能把参考项目的人名、数据、成果带入当前项目。
- 区分“完全一致”和“仅参考框架”：前者核对尺寸、字体、颜色、位置，后者保留当前项目的视觉规范。
- 查阅当前可用的 presentations 技能，遵循其模板、创作、渲染和最终化要求。需要导出PPT时加载当前 workspace dependencies，不硬编码某个用户、插件版本或运行时路径。读PDF或处理人像透明素材时再使用对应技能。
- 沿用已确认页数、标题、顺序和图片；只询问会影响制作的缺失信息，不增加无必要的确认步骤。

## 1. 写文字大纲

逐页给出：页码与标题、核心问题、版式与阅读顺序、各区域的实际文字、图示节点和连接关系、指定图片、页底一句总结。来源和待核实信息放在制作记录或备注中。

逻辑逐页递进，用短句和图示标签组织文字，避免大段文章。能用过程、关系、对照、结构说明的信息优先图示化。没有来源的数据不编造。

## 2. 生成HTML

- 先确定统一画布、背景、标题系统、字体和页底总结。默认宽屏16:9；用户指定模板比例时以模板为准。
- 背景铺满实际幻灯片画布。上传背景包含桌面、灰白边框或截图空白时，识别有效背景区域并裁去外围，不能保留灰色补边。
- 前景与人物照片保持比例。正文按段落建独立文本块，保留明确换行；避免逐字元素和脆弱的自动换行布局。
- 图示表达真实关系，用户要求可编辑时使用SVG或可转换的结构。避免各页全是同一种矩形卡片、过度整齐、箭头泛滥；流程、对照、环形、斜切框、主次人物布局可适当变化。
- 使用用户指定图片的最新版本，核对同名替换。人像需融入背景时保留透明边缘，不添加独立纯色底块。
- 保存到项目输出目录，素材自包含或采用可打包的相对路径。预览控件放在画布外。
- 用浏览器渲染检查溢出、遮挡、字号、裁切和总结。预览截图不能成为最终整页PPT对象。

## 3. 逐页修改

- 用户要求一页一页来时，先完成并展示当前页，等待反馈；“可以，继续”表示做下一页，不一次重做全稿。
- 只修改点名区域，保留已确认内容。更新图片后确认预览实际读取了新图，调整照片尺寸后核对对齐与裁切。
- 记录每页当前批准版本，必要时更新预览地址避开缓存，不导出旧稿。
- 用户纠正页码或主题后更新清单，防止漏页、重复和人员资料混淆。
- 当前页排版变动后回看；共用画布、背景或字体变化则检查所有受影响页面。

## 4. 合并导出SVG与可编辑PPT

在最终批准稿上操作，读取 [导出与验证](references/export-and-verify.md)。

- 按用户要求的页码顺序合并，不新增封面或结束页。HTML、SVG和PPT共用同一布局数据。
- PPT直接生成原生文本框、形状、连接线及图片对象。正文一段一个文本框，多行在同一个框内；强调字可以是框内富文本。
- SVG正文一段一个 `<text>`，包含显式换行，不使用 `<tspan>`、`foreignObject` 或文字轮廓。标题与独立标签可各自一个对象。
- 不承诺SVG“转换为形状”跨Office版本完全不变形，也不声称换行SVG必然转换成单个文本框。以直接生成的原生PPT满足整段编辑与稳定布局。
- 背景、照片、原案例截图和必须保留的艺术原稿保持图片对象；不谎称截图内部文字可单独修改。需要可编辑的表格或图示则另建原生对象。
- 最终背景满版、无外围灰框；前景不出画布，照片不拉伸，文字与艺术字用实际办公软件渲染核对。
- 完成 presentations 要求的最终检查，再运行本技能 `scripts/check_exports.py` 做基本结构检查；它不替代视觉验证。
- 交付完整PPTX与SVG压缩包，可附HTML入口；简述可编辑范围和艺术字所需字体。没有用户要求，不附制作脚本和校验日志。

## 调用与续作

调用示例：`使用 $ppt-html-workflow，基于这个文件夹的资料制作PPT，先给文字大纲，然后一页一页来。`

已有大纲或HTML获批时从相应阶段继续。用户仅要求导出或局部修改时，不强制重新走完前面阶段。
